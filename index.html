활동지 01 물리 엔진 기초

[활동지 01] 2D 물리 엔진의 기초: 화면과 중력, 그리고 점프

🎯 학습 목표

  1. 컴퓨터 화면의 좌표계와 게임 루프(Game Loop)의 동작 원리를 이해한다.
  2. 중력 가속도 수식을 코드로 모델링하여 캐릭터가 포물선 운동을 하도록 만든다.
  3. 바닥 착지 조건을 제어하여 무한 점프 버그를 방지한다.

1. 게임 루프와 화면 좌표계

컴퓨터 모니터는 수학 시간에 배우는 데카르트 좌표계와 달리 화면의 왼쪽 위가 원점 $(0, 0)$ 입니다.

  • $x$ 축: 오른쪽으로 갈수록 값이 커집니다 ($+$).
  • $y$ 축: 아래로 내려갈수록 값이 커집니다 ($+$).

게임은 멈춰 있는 그림이 아닙니다. "입력 받기 $\rightarrow$ 위치 계산하기 $\rightarrow$ 화면 새로 그리기" 과정을 1초에 60번씩 반복하는 게임 루프(Game Loop) 위에서 돌아갑니다.

📌 Step 1: 기본 창 띄우고 좌우로 움직이기

아래 코드를 복사하여 실행해 보세요. 방향키(←, →)를 눌러 사각형을 움직여 봅니다.

🐍 step1_basic_loop.py 
import pygame
import sys

# 1. 초기화 및 기본 설정
pygame.init()
SCREEN_WIDTH = 800
SCREEN_HEIGHT = 450
screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
pygame.display.set_caption("1차시: 플레이어 이동과 기본 루프")
clock = pygame.time.Clock()

# 2. 플레이어 기본 속성 (40x40 정사각형)
player_x = 100
player_y = 200
player_size = 40
speed = 5

# --- 게임 루프 ---
running = True
while running:
    # (1) 이벤트 감지 (창 닫기 등)
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # (2) 키보드 입력 처리
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        player_x -= speed
    if keys[pygame.K_RIGHT]:
        player_x += speed

    # (3) 화면 경계 이탈 방지
    player_x = max(0, min(player_x, SCREEN_WIDTH - player_size))

    # (4) 렌더링 (화면 지우고 새로 그리기)
    screen.fill((30, 30, 30))  # 어두운 회색 배경
    pygame.draw.rect(screen, (0, 200, 255), (player_x, player_y, player_size, player_size))  # 하늘색 네모
    pygame.display.flip()

    clock.tick(60)  # 60 FPS 고정

pygame.quit()
sys.exit()

2. 중력 가속도와 점프 (물리 법칙 도입)

우주 공간처럼 둥둥 떠다니는 사각형에 현실 세계의 중력을 부여해 봅시다.

왜 속도($v_y$)에 가속도($g$)를 계속 더할까?

  • 물체가 떨어질 때 속도는 일정하지 않고 점점 빨라집니다.
  • 매 프레임마다 세로 속도($v_y$)에 중력값($g$)을 누적해서 더해주면 자연스러운 자유낙하가 일어납니다.
$$v_y \leftarrow v_y + g$$
$$y \leftarrow y + v_y$$
  • 점프: 바닥에 닿아 있을 때 위쪽 방향으로 강한 초기 속도($-v_{\text{jump}}$)를 한 번 줍니다. (위쪽이 음수 방향이므로 마이너스 부호를 붙입니다.)
🧪 중력 & 점프 포물선 실시간 시뮬레이터 스페이스바 / 클릭으로 점프
중력 가속도 (gravity) 0.8
점프 초기 속도 (jump_power) -14.0
수평 이동 속도 (speed) 5.0
체공 시간: 35.0 frame 수평 도달 거리: 175 px

📌 Step 2: 중력과 점프 구현하기 (바닥 착지 제어)

아래 코드를 복사하여 Space 키로 점프를 테스트해 보세요.

🐍 step2_gravity_jump.py 
import pygame
import sys

pygame.init()
SCREEN_WIDTH = 800
SCREEN_HEIGHT = 450
screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
pygame.display.set_caption("1차시: 중력과 점프 물리 엔진")
clock = pygame.time.Clock()

# 플레이어 속성
player_x = 100
player_y = 100
player_size = 40
speed = 5

# 물리 파라미터
velocity_y = 0.0      # 세로 방향 현재 속도
gravity = 0.8         # 중력 가속도 (클수록 빨리 떨어짐)
jump_power = -14.0    # 점프 초기 속도 (음수: 위쪽)
is_grounded = False   # 바닥에 닿아있는지 여부

# 바닥 위치 (Y좌표)
FLOOR_Y = 380

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        
        # 키를 한 번 눌렀을 때만 점프 (누르고 있는 동안 계속 점프하는 것 방지)
        if event.type == pygame.KEYDOWN:
            if event.key == pygame.K_SPACE and is_grounded:
                velocity_y = jump_power
                is_grounded = False

    # 1. 좌우 이동 처리
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        player_x -= speed
    if keys[pygame.K_RIGHT]:
        player_x += speed
    player_x = max(0, min(player_x, SCREEN_WIDTH - player_size))

    # 2. 물리 연산 (중력 적용)
    velocity_y += gravity
    player_y += velocity_y

    # 3. 바닥 착지 판정 (Y 좌표 보정)
    if player_y + player_size >= FLOOR_Y:
        player_y = FLOOR_Y - player_size  # 발이 바닥 밑으로 파고들지 않게 고정
        velocity_y = 0.0                  # 떨어지던 속도를 0으로 리셋
        is_grounded = True                # 다시 점프할 수 있는 상태로 변경

    # 4. 화면 그리기
    screen.fill((25, 25, 35))
    
    # 바닥 그리기 (초록색)
    pygame.draw.rect(screen, (46, 204, 113), (0, FLOOR_Y, SCREEN_WIDTH, SCREEN_HEIGHT - FLOOR_Y))
    
    # 플레이어 그리기 (주황색 네모)
    pygame.draw.rect(screen, (230, 126, 34), (player_x, int(player_y), player_size, player_size))
    
    pygame.display.flip()
    clock.tick(60)

pygame.quit()
sys.exit()

활동지 02 충돌 판정

[활동지 02] 사각 충돌(AABB)과 너그러운 판정(Hitbox Inset)

🎯 학습 목표

  1. 두 사각형이 겹치는 수학적 조건(AABB 충돌)을 유도하고 코드로 구현한다.
  2. 축 분리($x$ 축, $y$ 축 분리 이동) 방식을 통해 발판 착지와 벽 막힘을 정확히 처리한다.
  3. 렌더링 박스와 피격 판정 박스를 분리(패딩 적용)하여 불합리하지 않은 난이도를 설계한다.

1. 사각형은 언제 부딪힐까? (AABB 충돌 판정)

두 직사각형 $A(x_1, y_1, w_1, h_1)$ 와 $B(x_2, y_2, w_2, h_2)$ 가 충돌하지 않고 완전히 떨어져 있는 경우는 4가지뿐입니다.

  1. $A$ 가 $B$ 의 완전 왼쪽에 있음: $x_1 + w_1 \le x_2$
  2. $A$ 가 $B$ 의 완전 오른쪽에 있음: $x_1 \ge x_2 + w_2$
  3. $A$ 가 $B$ 의 완전 위쪽에 있음: $y_1 + h_1 \le y_2$
  4. $A$ 가 $B$ 의 완전 아래쪽에 있음: $y_1 \ge y_2 + h_2$

따라서 두 사각형이 겹치는(충돌하는) 조건은 위 4가지 경우를 모두 벗어난 상태(드모르간 법칙의 여집합)입니다.

$$x_1 < x_2 + w_2 \quad \text{and} \quad x_1 + w_1 > x_2$$
$$y_1 < y_2 + h_2 \quad \text{and} \quad y_1 + h_1 > y_2$$

2. 축 분리(Separation of Axes) 이동의 필요성

$x$ 와 $y$ 좌표를 한꺼번에 더한 뒤 충돌을 검사하면 "벽에 옆으로 부딪힌 건지, 위에서 밟은 건지" 구별할 수 없어 캐릭터가 벽에 끼어버립니다.

  • 해결 순서:
    1. $x$ 축으로 먼저 이동 ($x \leftarrow x + v_x$) $\rightarrow$ 부딪히면 좌우 벽 충돌이므로 $x$ 위치를 벽 바로 앞/뒤로 밀어내고 $v_x = 0$.
    2. $y$ 축으로 이동 ($y \leftarrow y + v_y$) $\rightarrow$ 부딪히면:
      • 떨어지는 중($v_y > 0$): 발판 착지 $\rightarrow$ $y = \text{block.top} - h$, $v_y = 0$, 점프 가능 상태로 리셋.
      • 솟구치는 중($v_y < 0$): 머리 부딪힘 $\rightarrow$ $y = \text{block.bottom}$, $v_y = 0$ 으로 강제 낙하.

🛠️ 스프레드시트 작성 방법

  1. 구글 시트 / 엑셀 실행: 새 문서를 열고 열 너비와 행 높이를 정사각형 모양(예: $30 \times 30\text{ px}$)으로 조절합니다.
  2. 타일 ID 입력 규칙:
    • 0 또는 빈칸: 빈 공간 (허공)
    • 1 : 일반 안전 발판 블록 (착지 및 벽 충돌)
    • 2 : 위험 가시 장애물 (닿으면 사망/리스폰)
    • P : 플레이어 시작 위치 (스폰 지점)
    • G : 골인 지점 (스테이지 클리어 포탈)
  3. CSV 파일로 저장: 메뉴의 파일 $\rightarrow$ 다운로드 $\rightarrow$ 쉼표로 구분된 값(.csv)을 클릭하여 stage1.csv로 저장합니다.

2. 횡스크롤 카메라: 월드 좌표계 $\rightarrow$ 스크린 좌표계

맵의 가로 길이가 화면 너비($800\text{ px}$)보다 길어지면 실제 물체의 위치인 월드 좌표계와 모니터에 출력되는 스크린 좌표계를 분리해야 합니다.

  • 카메라 위치 ($\text{camera\_x}$): 플레이어가 화면의 정중앙선($\text{SCREEN\_WIDTH} / 2$)을 넘어설 때만 화면이 플레이어를 추적하도록 오프셋을 계산합니다.
$$\text{camera\_x} = \max(0, \text{player.centerx} - \text{SCREEN\_WIDTH} / 2)$$
  • 렌더링 위치 변환: 화면에 그리는 모든 오브젝트(발판, 가시, 플레이어 등)의 $x$ 좌표에서 $\text{camera\_x}$ 를 차감합니다.
$$\text{screen\_x} = \text{world\_x} - \text{camera\_x}$$

활동지 04 동적 기믹 & 조작감

[활동지 04] 동적 오브젝트(움직이는 발판·점프대)와 조작감 개선(코요테 타임)

🎯 학습 목표

  1. 일정한 구간을 왕복하는 움직이는 발판(Moving Platform)을 구현하고, 탑승한 플레이어의 좌표를 동기화한다.
  2. 밟았을 때 강한 수직 반발력을 주는 점프대(Trampoline) 기믹을 구현한다.
  3. 발판 끝에서 살짝 늦게 점프해도 입력을 인정해 주는 코요테 타임(Coyote Time)을 적용하여 조작감을 개선한다.

1. 동적 오브젝트: 움직이는 발판과 좌표 동기화

정적인 지형과 달리, 스스로 움직이는 발판은 발판의 이동 변위($\Delta x$)만큼 그 위에 서 있는 플레이어도 함께 이동시켜야 캐릭터가 미끄러져 떨어지지 않습니다.

  • 발판 왕복 메커니즘: 발판의 현재 위치가 시작점과 끝점 사이를 벗어나면 속도 부호를 반전($v_{\text{plat}} \leftarrow -v_{\text{plat}}$)합니다.
  • 탑승 판정 및 동기화 순서:
    1. 발판이 먼저 이동합니다 ($x_{\text{plat}} \leftarrow x_{\text{plat}} + v_{\text{plat}}$).
    2. 플레이어가 발판 위에 서 있는 상태(on_platform)라면 플레이어의 $x$ 좌표에도 발판의 이동량($v_{\text{plat}}$)을 더해줍니다.

2. 특수 기믹과 조작감 개선 (Game Juice)

(1) 점프대 (Trampoline / Spring Block)

플레이어가 하강 중($v_y > 0$) 점프대 블록 윗면에 닿았을 때, 일반 착지 대신 일반 점프보다 강력한 상향 속도($-v_{\text{bounce}}$)를 즉시 부여합니다.

(2) 코요테 타임 (Coyote Time)

만화 캐릭터가 절벽을 벗어나 허공을 밟아도 잠깐 동안 떨어지지 않는 연출에서 유래한 기법입니다. 발판에서 발이 떨어진 직후 $5 \sim 6\text{ frame}$ (약 0.1초) 동안은 공중에 떠 있어도 점프 입력을 허용하여, 플레이어가 억울하게 낙사하는 상황을 방지합니다.

$$\text{coyote\_timer} \leftarrow \begin{cases} \text{COYOTE\_FRAMES} & (\text{is\_grounded = True}) \\ \max(0, \text{coyote\_timer} - 1) & (\text{is\_grounded = False}) \end{cases}$$

1. 타격감의 핵심: 화면 흔들림 (Screen Shake)

캐릭터가 가시에 부딪혀 사망할 때 화면이 정적으로 멈추는 대신 강하게 흔들리면 즉각적인 시각적 충격을 전달할 수 있습니다.

원리와 수식 모델링

  • 흔들림 강도($S$)를 설정하고, 매 프레임마다 임의의 오프셋 $(\Delta x, \Delta y)$ 을 화면 렌더링 위치에 더해줍니다.
  • 흔들림 값은 가만히 유지되지 않고 매 프레임 감쇠 계수($\text{decay} \approx 0.9$)에 의해 점차 $0$ 으로 수렴합니다.
$$\Delta x = \text{random}(-\text{shake}, +\text{shake}), \quad \Delta y = \text{random}(-\text{shake}, +\text{shake})$$
$$\text{shake} \leftarrow \max(0, \text{shake} \times 0.9 - 0.1)$$

2. 사각 파티클(Particle) 폭발 물리 시스템

지오메트리 대시 스타일의 사망 연출은 하나의 큰 사각형이 여러 개의 작은 사각형 조각으로 깨져 사방으로 튀어나가는 구조입니다.

  • 파티클 속성: 위치 $(x, y)$, 무작위 속도 $(v_x, v_y)$, 크기($s$), 수명(Lifetime).
  • 매 프레임 갱신:
    • 중력 누적: $v_y \leftarrow v_y + g_{\text{particle}}$
    • 위치 이동: $x \leftarrow x + v_x, \quad y \leftarrow y + v_y$
    • 크기 축소: 수명이 다할수록 크기를 점차 줄여 자연스럽게 소멸 ($s \leftarrow s - \Delta s$).

# --- 절차적 8비트 효과음 생성 함수 (외부 wav 파일 불필요) ---
def generate_beep_sound(freq_start, freq_end, duration_ms, wave_type="square"):
    sample_rate = 44100
    n_samples = int(sample_rate * (duration_ms / 1000.0))
    buf = array.array('h')
    
    for i in range(n_samples):
        t = i / n_samples
        freq = freq_start + (freq_end - freq_start) * t
        phase = 2.0 * math.pi * freq * (i / sample_rate)
        
        if wave_type == "square":
            val = 16000 if math.sin(phase) >= 0 else -16000
        elif wave_type == "noise":
            val = random.randint(-16000, 16000)
        else:
            val = int(16000 * math.sin(phase))
            
        # 끝부분 부드럽게 감쇠 (클릭 노이즈 방지)
        decay = (1.0 - t)
        buf.append(int(val * decay))
        
    return pygame.mixer.Sound(buf)

class Particle:
    def __init__(self, x, y, color):
        self.x = x
        self.y = y
        self.color = color
        self.size = random.randint(6, 12)
        angle = random.uniform(0, 2 * math.pi)
        speed = random.uniform(3, 9)
        self.vx = math.cos(angle) * speed
        self.vy = math.sin(angle) * speed - 2  # 살짝 위로 솟구치도록
        self.gravity = 0.4
        self.life = 1.0  # 1.0 -> 0.0 으로 소멸
        self.decay = random.uniform(0.02, 0.04)

    def update(self):
        self.vy += self.gravity
        self.x += self.vx
        self.y += self.vy
        self.life -= self.decay
        self.size = max(0, self.size - 0.15)

🎯 학습 목표

  1. 파이썬의 csv 모듈을 활용하여 여러 개의 스테이지 파일(stage1.csv, stage2.csv 등)을 순차적으로 불러오는 다중 맵 로더를 구축한다.
  2. START, PLAYING, CLEAR, GAME_OVER로 이어지는 유한 상태 머신(FSM) 구조를 설계한다.
  3. 스테이지 클리어 시 다음 맵으로 자동 전환되고, 전 스테이지를 완주하면 최종 엔딩을 표시하는 완전한 게임 루프를 완성한다.

2. 유한 상태 머신 (FSM, Finite State Machine)

게임의 실행 상태를 상수로 정의하고, 하나의 메인 루프 안에서 현재 상태에 따라 키보드 입력 및 화면 렌더링을 분기 처리합니다.

🔄 게임 상태 전이도 (State Transition Flow) 
[STATE_START]      --(SPACE 키)---------> [STATE_PLAYING]
                                               │
                                 ┌─────────────┴─────────────┐
                         (가시 충돌 / 낙사)              (골인 도달)
                                 │                           │
                                 ▼                           ▼
                        [STATE_GAME_OVER]            [STATE_CLEAR]
                                 │                           │
                             (R 키: 재시도)             (SPACE 키: 다음 맵)
                                 │                           │
                                 └──────────> [STATE_PLAYING] <─┘
                                                     │ (마지막 스테이지 완주 시)
                                                     ▼
                                            [STATE_ALL_CLEAR]
